# 日用选物 · 商品购买 demo

## 项目用途与目标用户

一个可在本机运行的中文商品购买网站，用于体验商品浏览、购物车、优惠结算和订单管理的完整过程。适合产品体验人员、前端开发者和测试人员使用。所有交易、商品、库存与订单均为模拟；不收取真实款项，不连接支付平台，不需要账号、身份资料或银行卡。

## 启动

在本文件所在目录打开终端，运行：

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

浏览器访问 http://127.0.0.1:8000/index.html 。如端口被占用可换为 8001，同时更改访问地址。建议通过 HTTP 使用，不要双击文件；不需要 npm、安装依赖、联网服务或 CDN。根目录的 index.html、style.css、app.js 必须放在一起。商品图为页面内本地 SVG。

## 功能详情

- 10 件商品、居家/随行/文具/数码四类，支持名称搜索、分类、价格排序与空结果提示。
- 商品详情包含介绍、规格、库存及购买数量；提供不同价格、同价不同色、少量库存和售罄规格。
- 购物车支持加购、同规格累加、不同规格区分、增减数量、移除、单选和全选。
- 支持选择或输入两种优惠券，显示原价、优惠、优惠后金额、运费和总额。
- 测试收件信息验证、模拟下单、订单详情、取消订单、库存变化。
- 使用 localStorage 保存购物车、订单和库存，提供确认后恢复初始数据的入口。

## 业务规则

1. **价格与规格**：所有计算以整数“分”为单位，显示两位小数。列表展示最低规格价格。不同规格是不同条目；同规格重复加购应累计数量。数量须为正整数，且不超过该规格当前库存。搜索应忽略首尾空白；排序按列表展示价格进行数值比较。
2. **勾选范围**：仅勾选商品参与本次结算，未勾选商品不参与金额、优惠门槛或运费计算。购物车勾选状态应在刷新后保留。
3. **优惠**：每单最多使用一张券，可移除或替换。`SAVE20`：所选商品原价合计满 ¥200.00 减 ¥20.00；`NINE`：所选商品原价合计满 ¥100.00 打九折，优惠金额四舍五入到分。门槛不含运费。购物车变化后应重新判断资格与金额。无效券或未达门槛应提示，保留之前已成功使用的券。
4. **计算顺序**：商品原价合计 → 一张券的优惠 → 优惠后商品金额 → 运费 → 应付合计。优惠后满 ¥199.00（含）包邮，未满收 ¥12.00。无选中商品时运费为零，不能结算。例如：¥220.00 使用 SAVE20，优惠后 ¥200.00、运费 ¥0.00、合计 ¥200.00；¥100.00 使用 NINE，优惠后 ¥90.00、运费 ¥12.00、合计 ¥102.00。
5. **库存与订单**：加购不锁库存。提交前再次校验库存，提交时按各规格购买数量扣库存。仅移除本次购买条目，保留未选条目；快速重复提交不应生成重复订单。提交后的模拟订单可取消一次，按原规格实际购买数量恢复库存，不自动放回购物车。取消后保留订单详情和金额快照。
6. **持久化**：购物车及勾选状态、模拟订单、库存应刷新恢复。优惠券、未提交的收件信息不持久化。改变端口或浏览器会得到另一套本地数据。

## 核心任务与成功标准

|任务|操作目标|成功标准|
|---|---|---|
|选购合适商品|搜索或筛选，打开详情，切换规格和数量，加购|结果与条件相符，价格和库存对应所选规格，加购反馈明确|
|整理购物车|重复加购、区分规格、调整数量、移除、部分勾选|条目身份正确，数量在库存内，仅所选商品参与结算|
|比较优惠与运费|尝试有效/无效券、门槛附近金额，移除或替换优惠|优惠资格、分位金额、包邮门槛和计算顺序符合规则|
|完成模拟订单|填虚构信息，检查最终明细，提交、查看并取消|必填校验明确，订单只生成一次，库存扣减和恢复数量正确|
|恢复与重新测试|刷新浏览器，取消或确认重置|刷新保留应保存的数据；取消重置无变化，确认重置恢复初始状态|

## 真实限制与设计约束

- 这是单浏览器、单标签页的本地样例，无服务端、跨设备同步或多标签并发库存协调；localStorage 不是安全数据库。
- 无账号、实际支付、物流查询、税费、退货或退款；取消仅改变模拟订单及库存。
- 数据受浏览器存储配额和隐私设置影响，清理站点数据会丢失本地记录；没有订单导入、备份恢复功能。
- 两张示例券均可用于多次模拟订单，不涉及领券次数、有效期或叠加优惠。
- 收件信息只做基本格式校验，不校验真实地址与手机号；商品图片为示意图。
- 保持原生 HTML/CSS/JavaScript、本地资源和无构建启动方式；不接入外部接口，不上传数据。建议使用支持 dialog 的现代 Edge、Chrome 或 Firefox。

## 重点测试与额外验收要求

重点检查规格身份、数量限制、部分勾选、优惠门槛与重算、优惠后运费、订单库存闭环、刷新与重置。请同时覆盖正常流程和组合操作，以界面反馈及上述业务规则判断结果；不应仅以页面可打开作为通过标准。

桌面和手机宽度都应能访问完整功能；必填项错误不得生成订单；零库存规格应禁止加购；订单取消不得重复恢复；用户输入应作为文本展示；模拟提交不应有外部网络请求。发生问题时记录操作顺序、初始数据、实际/预期金额和库存、是否刷新。

## 重置

任意主页面底部点击“恢复初始测试数据”。选择“保留当前数据”不作修改；选择“确认恢复”清空购物车、模拟订单及表单，恢复表中库存，并回到商品列表。本操作只处理本商店 `everyday-shop-v1` 数据，不调用 localStorage.clear()。
